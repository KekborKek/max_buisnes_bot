# Задача аналитику: справочники для «Календаря обязательств»

**Срок: как можно скорее — сейчас это главный блокер.** Без этих трёх файлов бот на `/start` отвечает
«Не получилось», а мини-приложение не показывает календарь. Весь код готов и ждёт только данных.

Нужно положить в репозиторий три файла в папку `content/`:

| Файл | Что это | Кто его читает |
|---|---|---|
| `content/obligations.yaml` | Справочник обязательств ИП: сроки, инструкции, нормы | Календарь, напоминания, «Как сделать», карточка |
| `content/workdays.yaml` | Производственный календарь: праздники и перенесённые рабочие дни | Перенос срока с выходного на рабочий день |
| `content/nds.yaml` | Пороги освобождения от НДС и ссылки | Первое сообщение бота и ответ «платите ли вы НДС» |

Разработчики налоговых дат и сумм **не пишут** — только вы. В коде нет ни одной налоговой даты.

## 1. `content/obligations.yaml`

### Что должно быть (MVP, ~23 записи)

Профиль пилота — ИП на УСН «Доходы» без сотрудников. Нужны:

- три авансовых платежа по УСН и налог по УСН за год;
- декларация по УСН;
- уведомления об исчисленных суммах;
- фиксированные страховые взносы;
- 1% с дохода свыше 300 тыс. ₽;
- блок НДС для плательщиков: декларация и три платежа после каждого квартала.

Для **УСН 15%** — отдельные записи со своими шагами (решение D17), не ветвление внутри текста.

### Формат одной записи

```yaml
version: "2026-09-24"          # дата последней правки справочника целиком
obligations:
  - id: usn_advance_9m_usn6                  # латиница, уникальный, НЕ меняется никогда
    title: "Авансовый платёж по УСН за 9 месяцев"
    category: taxes                          # taxes | contributions | reports
    date_rule: { type: yearly, month: 10, day: 28 }
    shift: next_workday                      # next_workday | none
    applies_if:                              # все условия через И; не указано = любое значение
      regime: [usn6]
    needs_prep: true                         # true → напоминание ещё и за 30 дней
    norm: "НК РФ, ст. 346.21"
    source_url: "https://…"
    howto_steps:                             # РОВНО три шага, каждый — действие
      - "…"
      - "…"
      - "Пополните единый налоговый счёт на сумму аванса — до {due_date}."
    howto_link: { label: "Открыть ФНС", url: "https://…" }
    penalty_text: "Пени за каждый день просрочки, дальше — требование от налоговой."
    rule_version: 1
    last_checked_at: "2026-09-24"
```

### Правила дат — три вида

| `type` | Параметры | Что значит |
|---|---|---|
| `yearly` | `month` (1–12), `day` (1–31) | Раз в год, например 28 октября |
| `quarterly` | `offset_month` (1–3), `day` | Раз в квартал, `day`-го числа в `offset_month`-м месяце после конца квартала. Декларация за IV квартал — уже в следующем году |
| `monthly_in_quarter` | `months: [1, 2, 3]`, `day` | Несколько дат после каждого квартала — например, НДС тремя платежами |

Если в месяце нет нужного числа (31 апреля), берётся последний день месяца (решение D29) — **подтвердите, что так верно**.

### Кому показывать — `applies_if`

| Ключ | Значения |
|---|---|
| `regime` | список из `usn6`, `usn15`, `patent`, `ausn` |
| `income_band` | список из `lt10`, `10_20`, `20_60`, `gt60` |
| `has_employees` | `true` / `false` |
| `nds_payer` | `true` / `false` — для блока НДС ставьте `nds_payer: true` |

`applies_if: {}` — запись для всех. Других ключей быть не должно.

### Подстановки в шагах

Можно использовать **только `{due_date}`** — бот подставит «28 октября». `{notice_date}` и другие
не использовать: правила для них нет (решение D28). Если нужна другая дата — пишите её правилом
словами («до 25-го числа месяца срока»). **Подтвердите, что это подходит.**

### Что приведёт к пропуску записи

Запись с ошибкой в продукт не попадает (остальные загружаются), причина пишется в лог:
- нет любого из полей выше;
- `howto_steps` не ровно три непустые строки;
- `category`, `shift`, `regime`, `income_band` вне списков выше;
- неверные параметры правила даты;
- повтор `id` (вторая запись пропускается).

## 2. `content/workdays.yaml`

Официальный производственный календарь, **не по памяти**. Годы: **2026 и 2027** — календарь
собирается до 31 декабря следующего года. Если 2028 уже опубликован — добавьте и его: срок в конце
декабря 2027 может перенестись на январь 2028.

```yaml
2026:
  holidays: ["2026-01-01", "…"]   # нерабочие дни сверх суббот и воскресений
  workdays: []                    # рабочие субботы/воскресенья (переносы)
2027:
  holidays: ["…"]
  workdays: ["…"]
```

Файл целиком не загрузится, если: дата стоит не в своём году; одна дата одновременно в `holidays`
и `workdays`; формат даты не `ГГГГ-ММ-ДД`.

## 3. `content/nds.yaml`

```yaml
law: "Федеральный закон № … от …"
law_url: "https://…"
fns_guide_url: "https://…"
thresholds:              # доход за год → порог, действующий в следующем году
  - { income_years: [2025, 2026, 2027, 2028], limit_rub: 20000000 }
  - { income_years: [2029], limit_rub: 15000000 }
  - { income_years: [2030], limit_rub: 10000000 }
last_checked_at: "2026-09-24"
```

Один год дохода — только в одном пороге. Суммы — целым числом рублей. Значения выше — пример из спеки,
**сверьте их с законом**.

## Как проверить себя до отправки

Из корня репозитория (нужен `make setup`):

```bash
cd backend && .venv/bin/python -c "
from pathlib import Path
from app.calendar.loader import load_catalog, load_workdays, load_nds
c = load_catalog(Path('../content/obligations.yaml'))
print('обязательств загружено:', len(c.obligations))
print('лет в календаре:', sorted(load_workdays(Path('../content/workdays.yaml')).years))
print('порогов НДС:', len(load_nds(Path('../content/nds.yaml')).thresholds))
"
```

Если число загруженных обязательств меньше, чем вы написали, — выше в выводе будут строки
«Пропущена запись … : причина».
