# Спецификация «Календарь обязательств» — как с ней работать

Источник: спецификация UX/UI от 21.09.2026 (PDF команды), приведённая к формату для агента 23.09.2026.
Если PDF и эти файлы расходятся — **правы эти файлы**. Если эти файлы расходятся между собой — правее более конкретный: экран важнее общих правил, `decisions.md` важнее всего.

## Для агента: порядок чтения перед любой задачей

1. `docs/spec/product.md` — целиком. Продукт, словарь, общие правила для всех экранов.
2. `docs/spec/decisions.md` — решения по спорным местам. Не переоткрывай их.
3. Файл(ы) под задачу:
   - бэкенд, модели, справочник → `docs/spec/data-model.md`;
   - напоминания и планировщик → `docs/spec/reminders.md`;
   - экран → `docs/screens/NN-*.md`.
4. `docs/spec/plan.md` — какая задача сейчас и что в неё входит.

## Правила для агента

- **Одна задача = один экран или один модуль.** Не делай соседние экраны «заодно».
- **Тексты — только через ключи.** Бот: `content/texts.yaml` и функция `t("раздел.ключ")`. Мини-апп: `miniapp/src/texts.ts`. Ключи и тексты даны в файлах экранов — переноси их дословно. Если текста в спеке нет — не придумывай, поставь ключ и значение `TODO` и отметь в PR.
- **Не выдумывай данные о налогах.** Даты, нормы, пороги, штрафы — только из справочника `content/obligations.yaml` и конфига. В коде нет ни одной налоговой даты или суммы.
- **Слово `Event` занято** — это таблица аналитики (`app/core/models.py: Event`, функция `track`). Сущности календаря называются `Obligation*` / `Task` (см. `data-model.md`). Не путай.
- **Компоненты мини-аппа — из `@maxhub/max-ui` 0.5.0.** В нём есть: `Button`, `IconButton`, `ToolButton`, `CellList`, `CellSimple`, `CellHeader`, `CellAction`, `CellInput`, `Input`, `Textarea`, `Radio`, `Switch`, `Counter`, `Dot`, `Spinner`, `Typography`, `Avatar`. Чего нет — решено в `decisions.md` (D5–D8), своих компонентов сверх этого не заводи.
- Нашёл противоречие или дыру, которой нет в `decisions.md`, — **остановись и опиши её в PR**, не решай сам.

## Состав

| Файл | Что внутри |
|---|---|
| `product.md` | Что за продукт, словарь, сквозной путь, общие правила экранов, дисклеймеры, аналитика, чего нет |
| `data-model.md` | Справочник обязательств, профиль, задачи, отметки, уведомления, API мини-аппа |
| `reminders.md` | Схема 30/7/1/после срока, группировка, отмена, часовые пояса, повторная отправка |
| `decisions.md` | Решения по противоречиям PDF и открытые вопросы с дефолтами |
| `plan.md` | Порядок задач T1–T14 и критерии приёмки каждой |
| `../screens/*.md` | По файлу на экран. Нумерация как в гайде; экрана 4 нет (снят, см. D1) |
