# План реализации

Одна задача = одна ветка = один PR. Задачу не начинаем, пока не принята та, от которой она зависит. После каждой — ручной прогон сценария в MAX.

## Промпт для запуска задачи в Claude Code

```
Задача T<N> из docs/spec/plan.md.
Прочитай docs/spec/README.md и выполни порядок чтения оттуда.
Сделай только то, что входит в T<N>. Тексты — дословно из спеки, через ключи.
Перед кодом: коротко перечисли, какие файлы создашь и изменишь, и какие тесты напишешь.
В конце: прогон pytest / vitest / ruff / eslint, список «Готово, когда» из файлов экранов с отметками, что проверено.
Нашёл противоречие, которого нет в docs/spec/decisions.md, — остановись и опиши его.
```

## Критерии приёмки по задачам

**T0.** Всё из критериев T1 ниже. Плюс: `edit_message` и `open_app` — только со структурой, подтверждённой dev.max.ru/docs (ссылка в PR; не подтвердилось — в PR так и написано, метода нет). Цикл планировщика стартует и корректно останавливается в `lifespan`, падение одного тика не останавливает цикл — тест. `ZoneInfo("Asia/Vladivostok")` работает в Docker-образе. Контракты в `backend/app/calendar/` — сигнатуры и датаклассы, тела `NotImplementedError`; по ним T2 и T3 пишутся параллельно без правок контракта. `openapi.yaml` не меняется.

**T1.** Миграция применяется на пустой базе и на базе с существующими `User` и `Event`. Уникальный ключ `UserObligation` не даёт дублей. Ни одна новая таблица не называется `Event*`.

**T2.** Запись без любого обязательного поля пропускается с понятной строкой в логе и не роняет старт. `howto_steps` не из трёх элементов — тоже пропуск. Тесты на каждое поле.

**T3.** Минимум 200 параметризованных тестов дат: каждое правило × каждый месяц × переносы с субботы, воскресенья, праздников, конец года, 29 февраля. Производственный календарь в тестах — фикстура, не реальный файл аналитика.

**T4.** Профиль «УСН 6%, без сотрудников, доход 10–20» даёт ожидаемый набор из фикстуры. Повторная сборка идемпотентна. Уведомления в прошлом не создаются. Все тесты из `reminders.md` зелёные.

**T5.** Экраны 1, 2, 3, 5 проходят «Готово, когда». Тесты сценария на фикстурах апдейтов: полный путь, «Назад», текст вместо кнопки, повторный `/start`.

**T6.** Цикл отправки не держит транзакцию во время запроса к MAX. Тесты из `reminders.md`. Время: отправка в 10:00 по трём разным поясам.

**T7–T9.** «Готово, когда» соответствующих экранов. Для T8 — юнит-тесты на все форматы дат из экрана 9 и на случаи экрана 10.

**T10.** Каждый эндпоинт: 401 без `initData`, чужой `id` → 404, идемпотентность `done`. `status` считается на бэкенде в поясе пользователя — тест на границу суток во Владивостоке.

**T11–T13.** «Готово, когда» экранов; vitest на каждое из четырёх состояний экранов 14 и 16; `npm run lint` и `npm run build` без ошибок; ручная проверка в мобильном и веб-MAX со скриншотами в PR.

**T13, демо.** `/demo_remind d7` от админа присылает напоминание за секунды; от не-админа — ответ экрана 10. Решение 28.09 — открыта всем.
