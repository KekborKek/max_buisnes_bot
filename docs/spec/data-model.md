# Данные

Весь календарь собирается из одного справочника обязательств плюс ответов пользователя. Внешних API нет: ни ФНС, ни банка, ни ЕГРИП.

## 1. Справочник обязательств — `content/obligations.yaml`

Редактирует аналитик, не разработчик. Загружается при старте, валидируется. **Запись без любого обязательного поля не попадает в продукт** — загрузчик пишет её id в лог и пропускает.

```yaml
version: "2026-09-20"          # дата последней правки справочника целиком
obligations:
  - id: usn_advance_9m                       # латиница, уникальный, не меняется никогда
    title: "Авансовый платёж по УСН за 9 месяцев"
    category: taxes                          # taxes | contributions | reports
    date_rule:                               # см. «Правила дат» ниже
      type: yearly
      month: 10
      day: 28
    shift: next_workday                      # next_workday | none
    applies_if:                              # все условия через И; поле не указано = любое значение
      regime: [usn6, usn15]
    needs_prep: true                         # true → напоминание за 30 дней
    norm: "НК РФ, ст. 346.21"
    source_url: "https://…"
    howto_steps:                             # ровно 3, каждый — действие
      - "Посчитайте аванс: 6% с дохода за 9 месяцев минус уплаченные взносы и прошлые авансы."
      - "Подайте уведомление об исчисленной сумме — до {notice_date}."
      - "Пополните единый налоговый счёт на сумму аванса — до {due_date}."
    howto_link: { label: "Открыть ФНС", url: "https://…" }
    penalty_text: "Пени за каждый день просрочки, дальше — требование от налоговой."
    rule_version: 1
    last_checked_at: "2026-09-20"
```

| Поле | Обязательно | Где видно |
|---|---|---|
| `id` | да | нигде |
| `title` | да | 5, 6, 8, 14, 15, 16 |
| `category` | да | метка в 14, 15, 16 |
| `date_rule` + `shift` | да | везде, где есть дата |
| `applies_if` | да (может быть `{}`) | нигде — решает, попадёт ли в календарь |
| `needs_prep` | да | нигде — решает, будет ли напоминание за 30 дней |
| `norm` | да | 7, 16 |
| `source_url` | да | 16 |
| `howto_steps` (ровно 3) | да | 7, 16 |
| `howto_link` | да | 7 |
| `penalty_text` | да | 6, 16 |
| `rule_version` | да | нигде |
| `last_checked_at` | да | 7, 11, 16 |

Разные режимы с разной инструкцией — **разные записи** (`usn_advance_9m_usn6`, `usn_advance_9m_usn15`) с разным `applies_if`. Ветвлений по режиму внутри текста нет.

### Правила дат

| `type` | Параметры | Пример |
|---|---|---|
| `yearly` | `month`, `day` | 28 октября каждого года |
| `quarterly` | `offset_month` (1–3 после конца квартала), `day` | НДС-декларация: 25-е число месяца после квартала |
| `monthly_in_quarter` | `months: [1,2,3]` после квартала, `day` | НДС-платёж равными долями: 28-е числа трёх месяцев после квартала |

`shift: next_workday` — если дата выпала на нерабочий день по производственному календарю, срок переносится на ближайший рабочий. Показываем и исходную, и итоговую дату (см. экран 3, 6).

### Производственный календарь — `content/workdays.yaml`

```yaml
# Нерабочие дни сверх суббот и воскресений и рабочие субботы/воскресенья
2026:
  holidays: ["2026-01-01", …]
  workdays: []         # перенесённые рабочие выходные
2027:
  holidays: […]
  workdays: […]
```

Заполняет аналитик по официальному производственному календарю. **Разработчик не вписывает даты по памяти** — только из файла. Если года нет в файле, сборка календаря на этот год падает с понятной ошибкой в логе.

### Конфиг НДС — `content/nds.yaml`

```yaml
law: "Федеральный закон № 228-ФЗ от 04.07.2026"
law_url: "https://…"
fns_guide_url: "https://…"
thresholds:              # доход за год → порог, действующий в следующем году
  - { income_years: [2025, 2026, 2027, 2028], limit_rub: 20000000 }
  - { income_years: [2029], limit_rub: 15000000 }
  - { income_years: [2030], limit_rub: 10000000 }
last_checked_at: "2026-09-20"
```

Порог и годы в тексты не зашиваются: тексты экранов 1 и 3 подставляют значения отсюда.

### Что в справочнике MVP

Около 23 записей на профиль «УСН, без сотрудников»: три аванса и годовой налог по УСН, декларация, уведомления об исчисленных суммах, фиксированные взносы до 28 декабря, 1% с дохода свыше 300 тыс. ₽ до 1 июля. Для плательщика НДС — блок НДС: декларация до 25-го и три платежа до 28-го после каждого квартала.

**Заполнение справочника — задача аналитика, не агента.** Агент делает загрузчик, валидацию и две тестовые записи в `backend/tests/fixtures/obligations.yaml`.

## 2. Таблицы

Имя `Event` занято аналитикой. Новые таблицы:

### `Profile` (1:1 с `User`)

| Поле | Тип | Значения |
|---|---|---|
| `user_id` | PK, FK → `User` | |
| `income_band` | str | `lt10` · `10_20` · `20_60` · `gt60` · `unknown` |
| `regime` | str | `usn6` · `usn15` · `patent` · `ausn` · `unknown` |
| `has_employees` | bool | |
| `timezone` | str | IANA, по умолчанию `Europe/Moscow` |
| `nds_payer` | bool | вычисляется при сохранении из `income_band` и `nds.yaml` |
| `started_at` | datetime | первый `/start` — для метрики времени |
| `calendar_built_at` | datetime, null | признак «календарь собран» |
| `reminders` | JSON | настройки экрана 13: `{"d30": true, "d7": true, "hour": 10}` |

### `UserObligation` — обязательство в календаре конкретного пользователя

| Поле | Тип | Смысл |
|---|---|---|
| `id` | PK | |
| `user_id` | FK | |
| `obligation_id` | str | `id` из справочника |
| `rule_version` | int | версия записи на момент сборки |
| `original_date` | date | дата по правилу |
| `due_date` | date | после переноса на рабочий день |
| `done_at` | datetime, null | отметка |
| unique | (`user_id`, `obligation_id`, `due_date`) | повторная сборка не плодит дубли |

### `Task` — своя задача

| Поле | Тип | Смысл |
|---|---|---|
| `id` | PK | |
| `user_id` | FK | |
| `title` | str ≤ 60 | |
| `due_date` | date | не раньше сегодняшнего при создании |

### `Notification` — запланированное сообщение

| Поле | Тип | Смысл |
|---|---|---|
| `id` | PK | |
| `user_id` | FK | |
| `item_type` | str | `obligation` · `task` · `week` (записи сводки `digest`, `calendar/digest.py`) |

### `WrongDateReport` — кнопка «Неверный срок»

`id`, `user_id`, `obligation_id`, `due_date`, `created_at`. Просмотр — прямым запросом к базе, интерфейса не нужно.

## 3. API мини-приложения

Все эндпоинты — под проверкой `initData`, как существующий `/api/me`. Сначала контракт в `openapi.yaml`, потом код.

| Метод | Путь | Что | Экраны |
|---|---|---|---|
| GET | `/api/me` | уже есть; добавить `has_profile`, `profile` | 14, 18, 19 |
| GET | `/api/calendar?from=YYYY-MM-DD&to=YYYY-MM-DD` | список `CalendarItem` за период + все просроченные | 14, 15 |
| GET | `/api/items/{type}/{id}` | одна карточка со всеми полями | 16 |
| POST | `/api/items/{type}/{id}/done` | отметить; идемпотентно | 16 |
| DELETE | `/api/items/{type}/{id}/done` | снять отметку | 16 |
| POST | `/api/obligations/{id}/report` | «Неверный срок» | 16 |
| POST | `/api/tasks` | создать задачу | 17 |
| PATCH | `/api/tasks/{id}` | изменить задачу | 17 |
| DELETE | `/api/tasks/{id}` | удалить задачу | 16 |

`CalendarItem` (DTO):

```json
{
  "type": "obligation",
  "id": 42,
  "title": "Авансовый платёж по УСН за 9 месяцев",
  "category": "taxes",
  "due_date": "2026-10-28",
  "original_date": "2026-10-28",
  "status": "upcoming",
  "done_at": null
}
```

Карточка (`GET /api/items/...`) — то же плюс `norm`, `source_url`, `howto_steps`, `howto_link`, `penalty_text`, `last_checked_at`; у задачи — `remind_offset_days`, `remind_hour`, `remind_minute`. `status` считает бэкенд в поясе пользователя; фронт его не пересчитывает.
