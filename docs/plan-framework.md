> Составлен 16.09.2026, до выбора идеи продукта (по STATUS — выбор 18.09).
> Задачи в нём **не зависят от идеи**: это несущие конструкции, на которые ляжет продукт.
> Источник истины по каждой задаче — GitHub Issue. Здесь — карта, порядок и связи.

## Как агенту работать с этим файлом

1. Найти свою задачу в таблице → открыть issue: `gh issue view <номер>`.
2. Прочитать `AGENTS.md` целиком. Раздел «Можно менять» в issue — жёсткая граница.
3. Проверить, что задачи, от которых зависит твоя, уже слиты (колонка «Зависит от»).
4. План (≤7 шагов) → подтверждение человека → реализация → `make lint && make test` → PR с `Closes #<номер>`.

Правила, о которые чаще всего спотыкаются:
- тексты только через `t("раздел.ключ")` и `texts.*`, в коде не хардкодить;
- каждое значимое действие — `ctx.track(...)` / `api.track(...)`;
- методы MAX API и Bridge — только из `docs/max-api-notes.md`, по аналогии с Telegram не выдумывать;
- секретов нет ни в коде, ни в тестах, ни в логах.

## Состояние каркаса на 16.09.2026

Что уже есть и работает: вебхук с быстрым 200 и обработкой в фоне, идемпотентность апдейтов,
роутер с четырьмя способами регистрации, FSM в БД, проверка подписи initData, адаптер Mock/Real,
CI (ruff, pytest, сборка фронта, `docker compose build` с лимитом 5 минут, gitleaks по всей истории).

Чего нет: связки «бот → мини-апп» (кнопка `open_app`, диплинки), настроек конкурентности SQLite,
ретраев в клиенте MAX, экранов и обработки 401 в мини-аппе, способа посмотреть собранную аналитику.

**Главный риск — не код.** Весь слой `bot/` построен на фикстурах, собранных по документации
и помеченных **[сверить]** в `docs/max-api-notes.md`. Пока не получен токен и не сняты реальные
апдейты (`CAPTURE_UPDATES=true`), не проверено ни одно предположение о структуре `message_created`,
`message_callback` и `bot_started`. Это задача №1 на момент появления токена.

## Порядок и параллельность

Задачи внутри одной волны не пересекаются по файлам — их можно вести одновременно.

```
Волна 1 (сегодня)     #7  #8  #9  #10        LEAD, файлы не пересекаются
                      #16                     API, только тесты
Волна 2 (завтра)      #12 ──┬──▶ #13          API → BOT
                            └──▶ #14          API → FRONT
                      #11                     BOT, независимо
                      #15                     FRONT, независимо
Волна 3 (после 18.09) #17 #19 #20 #21         добираются фоном
                      #18                     после #15
```

Что нельзя параллелить:
- #12 строго раньше #13 и #14 — они читают поле, которого до неё нет;
- #13 и #11 оба трогают `backend/app/bot/` — вести последовательно или одним агентом;
- #18 после #15 — иначе тесты пишутся на код, который тут же переписывают.
