# Экран 10. Бот не понял или сервис не работает

**Где:** бот. Три разных ответа. Главное правило: **из любого есть выход одним нажатием.**

## Что видит пользователь

```yaml
fallback:
  unknown: "Я понимаю сроки и задачи. Напишите, например: «оплатить аренду 5 ноября»."
  no_date: "Понял задачу «{title}», но не увидел дату. Когда напомнить?"
  service: "Не получилось. Проверьте интернет и нажмите «Повторить». Ваши данные на месте."
  unknown_3: "Если нужного нет в календаре, напишите нам."
  service_2: "Сервис временно недоступен. Напоминания придут в срок, календарь не потерян."
  btn_open: "Открыть календарь"
  btn_about: "О сервисе"
  btn_tomorrow: "Завтра"
  btn_week: "Через неделю"
  btn_pick: "Выбрать дату"
  btn_retry: "Повторить"
  btn_write: "Написать нам"
```

| Случай | Когда | Текст | Кнопки |
|---|---|---|---|
| Не понял | Нет ни даты, ни похожего на задачу текста | `unknown` | «Открыть календарь» «О сервисе» |
| Не нашёл дату | Похоже на задачу (есть глагол / от 2 слов), даты нет | `no_date` | «Завтра» «Через неделю» / «Выбрать дату» |
| Сервис не ответил | Исключение при обработке | `service` | «Повторить» |

## Действия

| Кнопка | Куда |
|---|---|
| «Завтра», «Через неделю» | Экран 9 с подставленной датой. Payload `fb:tomorrow:<id>` / `fb:week:<id>` — id своего черновика; из старого сообщения — `task.draft_stale`, ничего не предлагает (#96) |
| «Выбрать дату» | `open_app` (`start_param = task_draft_<id>`) → экран 17 с названием; из старого сообщения — пустая форма и тост (#96) |
| «Повторить» | Повтор последнего действия пользователя |
| «Открыть календарь» | Экран 14 |
| «О сервисе» | Экран 11 |
| «Написать нам» | Обращение в боте (D13, «Написать нам» ниже): payload `feedback:start:fallback` |

## Состояния

- **Три непонятых сообщения подряд:** к `unknown` добавляется `unknown_3` и кнопка «Написать нам» — всегда, `SUPPORT_URL` не нужен.
- **Два сбоя подряд:** вместо `service` — `service_2`.
- Счётчики — в `DialogState`, сбрасываются любым успешным действием.

## Данные

Последнее действие пользователя для «Повторить» (`DialogState`). Существующий `handlers/fallback.py` переписывается под эти тексты; старые ключи `errors.*` удаляются, когда на них не останется ссылок.

## Аналитика

- `fallback_shown` с `case`
- `date_not_parsed` — на случай «не нашёл дату»
- `feedback_started` / `feedback_sent` / `feedback_cancelled` — «Написать нам», см. ниже

## «Написать нам» — обращение в боте (D13, 28.09)

Общее для экранов 10 и 11, код — `handlers/feedback.py`. Тексты `feedback.*` в `content/texts.yaml` — **временные тексты техлида (28.09), ждут UX**.

| Шаг | Что происходит |
|---|---|
| «Написать нам» (`feedback:start:about` / `feedback:start:fallback`) или `/feedback` | `feedback.prompt` + «Отмена»; состояние `feedback_wait` |
| Текст до 2000 символов | Сохраняется в `feedback`, ответ `feedback.sent`, ожидание снято; пересылка каждому из `ADMIN_IDS`: `feedback.forward` («Обращение #id от имя, id: текст») |
| Длиннее 2000 | `feedback.too_long`, ждём дальше — не обрезаем, чтобы не потерять конец |
| Пусто или не текст (фото, стикер) | `feedback.empty`, ждём дальше |
| «Отмена» | `feedback.cancelled`, ничего не сохраняется |
| Команда или другая кнопка | Работает как обычно и снимает ожидание |
| `/feedback <текст>` | Сохраняется сразу, без вопроса |
| Больше 5 обращений за час от одного пользователя | `feedback.rate_limited`, ничего не сохраняется, в ожидание не ставим |
| Групповой чат | «Написать нам» не показывается; `/feedback`, `/feedback_list`, кнопка из старого сообщения — ответ «не понял»; текст в группе посреди ожидания из лички — не обращение, ожидание снимается |

- Пересылка — после коммита и после ответа пользователю; её ошибка ответ не ломает: лог и `forwarded = false`. Без `ADMIN_IDS` — только сохранение и предупреждение в лог.
- `/feedback_list` — последние 10 обращений (время по Москве, «не переслано», первые 100 символов), без разметки (`format` не передаём: чужой `[x](url)` не станет ссылкой); только `ADMIN_IDS` и только в личке, остальным — случай «не понял».
- Для внешнего ключа создаётся только `User`, `Profile` — нет: обращение не попадает в воронку «начали».
- Аналитика: `feedback_started {source}`, `feedback_sent {length}`, `feedback_cancelled`.

## Не делаем

Не отвечаем на вопросы про налоги в свободной форме.

## Готово, когда

- [ ] Ни в одном тексте нет кода ошибки и слова «сервер»
- [ ] Каждый из трёх случаев воспроизводится на демо одним действием
- [ ] После «Повторить» человек продолжает с того же места
- [ ] «Написать нам» после трёх непонятых сообщений есть и без `SUPPORT_URL`; обращение сохраняется и приходит `ADMIN_IDS`
