# Экран 18. Мини-приложение открыли не через бота

**Где:** мини-приложение. Прямой вход по ссылке или из веб-версии MAX, до прохождения онбординга. **Жюри проверяет именно этот случай.**

## Логика входа

| `/api/me` | Что показываем |
|---|---|
| профиль есть, событий > 0 | Экран 14, никаких заглушек |
| профиль есть, событий 0 | Экран 14, состояние «пусто» |
| профиля нет | Заглушка ниже |
| 401 / сессия не определилась | Та же заглушка, **без сообщения об ошибке авторизации** |

## Что видит пользователь

```ts
gate: {
  title: "Календарь собирается в чате",
  text: "Ответьте на четыре вопроса — это займёт минуту.",
  openChat: "Открыть чат",
},
```

Кнопка «Открыть чат» (`Button`, основная).

## Действия

| Кнопка | Что происходит |
|---|---|
| «Открыть чат» | MAX Bridge: открыть диалог с ботом; если метод недоступен (веб-версия) — ссылка на бота. Пользователь попадает на экран 1 |

После сборки календаря повторное открытие мини-приложения показывает уже список.

## Состояния

- **Грузится:** `Spinner` по центру, не дольше ответа `/api/me`.
- **Ошибка сети:** та же заглушка + общая плашка с «Повторить».

## Данные

`/api/me` → `has_profile`, число событий. Больше ничего.

## Аналитика

`miniapp_opened` с `has_profile = false` (пишет бэкенд).

## Готово, когда

- [ ] Прямой вход не показывает пустой экран и не падает
- [ ] Из заглушки есть путь в бота одним нажатием
- [ ] Случай проверен в мобильной и в веб-версии
- [ ] Слова «авторизация», «сессия», «401» пользователь не видит
