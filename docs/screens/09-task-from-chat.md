# Экран 9. Своя задача текстом

**Где:** бот. Ответ на любое свободное сообщение, в котором распознана дата. Делает продукт полезным между налоговыми датами.
**Когда срабатывает:** после завершения онбординга. До него свободный текст обрабатывает экран 2 (`use_buttons`).

## Что видит пользователь

Пользователь пишет «оплатить аренду 5 ноября» и получает:

```yaml
task:
  confirm: "Задача: «{title}». Срок — {date}, напомню {remind_when} в {time}. Сохранить?"
  saved: "Добавил. Всего в календаре {count} {count_word}."
  past_date: "{date} уже прошло. Сохранить на {next_year_date}?"
  duplicate: "Такая задача уже есть на {date}."
  cancelled: "Хорошо, не сохраняю."
  btn_save: "Сохранить"
  btn_edit: "Изменить"                 # D12
  btn_cancel: "Отмена"
  btn_add_anyway: "Добавить всё равно"
  btn_yes: "Да"
  btn_open: "Открыть календарь"
```

- `{title}` — текст сообщения без распознанной даты и времени, первая буква заглавная, обрезан до 60 символов.
- `{remind_when}` — «за день» (`task.remind_day`, по умолчанию); если в сообщении есть время — «в день срока» (`task.remind_same_day`, временный текст техлида, #103).
- `{time}` — «10:00» по умолчанию или время из сообщения: час без ведущего нуля, минуты двумя цифрами («9:05», «15:30»). Так же пишет мини-апп.
- Напоминание уже не успеет (задача на сегодня, время прошло) — `confirm_no_remind`.

Кнопки подтверждения: «Сохранить» / «Изменить» «Отмена». После сохранения — `saved` + «Открыть календарь».

## Разбор даты

Правилами, без языковой модели. Поддерживаем четыре формата:

| Формат | Пример | Результат |
|---|---|---|
| число + месяц словом | «5 ноября», «5 нояб» | ближайшее такое число, не в прошлом, иначе `past_date` |
| ДД.ММ(.ГГГГ) | «05.11», «5.11.2026» | то же |
| относительный день | «сегодня», «завтра», «послезавтра», «через неделю» | «через неделю» — те же +7 дней, что и кнопка «Через неделю» (экран 10) |
| день недели | «в понедельник», «в пн» | ближайший будущий такой день; сегодняшний не считается |

Дата не найдена → экран 10, случай «не нашёл дату». Слова без даты и без действия → экран 10, «не понял».

## Разбор времени (#103)

Время разбирается вместе с датой и вырезается из названия. Без даты время не теряется: экран 10, а «Завтра», «Через неделю» и «Выбрать дату» (форма 17) получают его из черновика.

| Формат | Пример | Время |
|---|---|---|
| ЧЧ:ММ, с «в», «с» или без предлога | «15:30», «в 15:30», «в 9:05», «03:00» | 15:30, 9:05, 3:00 |
| час с «ч/час/часа/часов» (только с «в») | «в 15 ч», «в 3 часа» | 15:00 |
| час + часть суток | «в 9 утра» (1–11), «в 3 дня» (12, 1–5), «в 7 вечера» (4–11), «в 12 ночи» (12, 1–4) | 9:00, 15:00, 19:00, 0:00 |
| голое «в N» — только в конце текста, перед знаком препинания или прямо перед датой | «встреча завтра в 15», «в 15 завтра маме» | 15:00 |
| диапазон — время начала, вырезается целиком | «с 15:00 до 16:00», «15:00–16:00» | 15:00 |

- **Часы 1–6 без «утра» / «ночи» — дневные:** «в 3», «в 3 часа» — 15:00, «3:30» — 15:30. С ведущим нулём — как написано: «03:00» — 3:00.
- **«до / к / не позднее» + время — срок внутри дня, а не время напоминания:** «Сдать отчёт до 18:00 5 ноября» — название «Сдать отчёт до 18:00», напоминание по умолчанию (за день в 10:00).
- Голое «в N» перед словом — не время: «в 2 этапа», «в 4 квартале», «в 11 кабинете», «в 15 минут». «ждать 3 часа» (без «в») — длительность.
- Точка — только дата: «10.05» — 10 мая, «10:05» — время, «в 12.30» — ни то ни другое. Число со словом суммы после него («на 10:30 руб», «1.5 млн») — не время и не дата.
- Недопустимое время («25:00», «12:60», «в 5 ночи») остаётся в названии.
- Время есть → напоминание **в день срока в это время** (`remind_offset_days = 0`). Нет → за день в 10:00, как раньше.

## Действия

| Кнопка | Что происходит | Куда |
|---|---|---|
| «Сохранить» | Создаёт `Task` и `task`-уведомление | `saved` + «Открыть календарь» |
| «Изменить» | `open_app` со `start_param = task_draft_<id>` — id своего черновика (#96) | Экран 17 с заполненными названием и датой; черновик уже не этот — пустая форма и тост `form.draftStale` |
| «Отмена» | Ничего не сохраняет | `cancelled` |
| «Да» (на `past_date`) | Дата → тот же день следующего года | снова `confirm` |
| «Добавить всё равно» | Создаёт дубль | `saved` |

## Состояния

- **Дата в прошлом:** `past_date` + «Да» «Отмена».
- **Задача с таким же названием и датой уже есть:** `duplicate` + «Добавить всё равно» «Отмена».
- **Сохранение не прошло:** `common.error` + «Повторить»; текст задачи не теряется (черновик в `DialogState`).

## Данные

`Task.title`, `due_date`, `remind_offset_days = 1`, `remind_hour = 10`, `remind_minute = 0`; со временем в сообщении — `remind_offset_days = 0` и время из сообщения (#103). Категория всегда `custom`. Напоминание — одно (D11).

Черновик: `DialogState.data["task_draft"] = {title, due_date, id[, remind_hour, remind_minute]}` — ключи времени только вместе и только если время было; `/api/me` отдаёт их в `draft` (иначе оба `null`).

## Аналитика

`task_created` с `source = chat`, `remind_offset = 1` (со временем в сообщении — `0`).

## Не делаем

Не распознаём повторы («каждый месяц») и время словами без числа («в полдень», «вечером»). Не используем LLM.
«Через неделю» — только эта фраза целиком, не «через 2 недели» и не «через 10 дней».

## Готово, когда

- [ ] Все четыре формата даты из таблицы разбираются; на каждый есть юнит-тест
- [ ] Задача появляется в списке и в сетке месяца с меткой «Своё»
- [ ] Напоминание по задаче приходит в срок
- [ ] Нераспознанная дата не теряет текст задачи
- [ ] «Изменить» открывает форму с уже заполненными полями
- [ ] «…5 ноября в 15:30» → «напомню в день срока в 15:30», напоминание в 15:30 по поясу пользователя (#103)
