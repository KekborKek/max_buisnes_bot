- **Лёгкая миграция схемы** (#99, `core/db.py`, ADR в `docs/decisions.md`): при старте после `create_all`
  недостающие безопасные колонки (nullable или со скалярным/серверным default, не PK/UNIQUE) добавляются
  `ALTER TABLE … ADD COLUMN` с `log.warning`; остальное (NOT NULL без default, лишняя колонка, другая affinity,
  unique-индекс) — только `log.error`, старт не падает, ничего не удаляется. **Правило для правок моделей:**
  новые колонки — nullable или со скалярным default; не удалять и не переименовывать; индекс на существующей
  колонке — вручную. Чистка `processed_updates` старше 24 ч — при старте. `make db-reset` — только локально,
  отказывает при `APP_ENV=prod` и при наличии тома `max-business-bot_caddy-data` (на Маке техлида он есть —

### Как работаем с агентами
- Планировщик создаёт worktree `../mbb-<задача>` и ветку заранее; агент работает только там.
  Симлинки `.venv`/`node_modules` в worktree не в `.gitignore` — агентам: `git add` только поимённо.
- Агент показывает план и ждёт «ок»; ведёт журнал передачи `scratchpad/handoff/<задача>.md`.
  24.09 агенты трижды обрывались на ошибках API — журнал и «продолжи с того места» спасали работу.
- Не больше ~4 агентов на opus одновременно; простое — на sonnet.
- Планировщик ревьюит PR (субагент `reviewer` для больших) и гоняет тесты на слиянии всех PR волны
  с текущим main. Сливает и деплоит — **только по команде человека**.
- `docs/prompts/executor.md` содержит путь журнала передачи от старой сессии — при запуске агента
  давать ему путь `scratchpad/handoff/` текущей сессии (так сделано для FRONT-21).
- Старые слитые worktree убраны 27.09. Не трогать без человека: `mbb-bug-2` (ветка `fix/bug-2` **не слита**), `mbb-bug-1` и `mbb-issue-12_13`
  (слиты, но есть незакоммиченные файлы).
- Вебхук подписан: агентам нельзя `make dev-bot` для живой проверки и нельзя `webhook.py set/delete`.
  Живую проверку делает человек после деплоя.
