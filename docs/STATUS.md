### Как работаем с агентами
- Планировщик создаёт worktree `../mbb-<задача>` и ветку заранее; агент работает только там.
  Симлинки `.venv`/`node_modules` в worktree не в `.gitignore` — агентам: `git add` только поимённо.
- Агент показывает план и ждёт «ок»; ведёт журнал передачи `scratchpad/handoff/<задача>.md`.
  24.09 агенты трижды обрывались на ошибках API — журнал и «продолжи с того места» спасали работу.
- Не больше ~4 агентов на opus одновременно; простое — на sonnet.
- Планировщик ревьюит PR (субагент `reviewer` для больших) и гоняет тесты на слиянии всех PR волны
  с текущим main. Сливает и деплоит — **только по команде человека**.
- Вебхук подписан: агентам нельзя `make dev-bot` для живой проверки и нельзя `webhook.py set/delete`.
  Живую проверку делает человек после деплоя.
